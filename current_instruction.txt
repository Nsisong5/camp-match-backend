CHUNK 2 — DOMAIN MODEL
[FOR YOU — GEMINI CLI]
Files to modify: domain/value_objects.py, domain/entities.py.
value_objects.py:
Coordinates — latitude (float, must be between -90 and 90 inclusive), longitude (float, must be between -180 and 180 inclusive) — raise ValueError at construction otherwise.
InstitutionType (enum) — UNIVERSITY, POLYTECHNIC, COLLEGE_OF_EDUCATION, OTHER.
InstitutionStatus (enum) — ACTIVE, INACTIVE. Shared by both University and Campus.
A small normalization function, normalize_name(raw: str) -> str — trim, lowercase, collapse internal whitespace to single spaces. Used by both entities below and by the uniqueness checks in Chunk 3 — put it here once, don't duplicate it.
entities.py:
University — id (shared-kernel EntityId), official_name (required, 1–200 characters), normalized_name (derived via normalize_name, not independently settable), short_name (optional), institution_type (InstitutionType), status (InstitutionStatus, defaults ACTIVE), country (defaults "Nigeria"), state_region (optional), source/external_reference (optional, per Part 16 — provenance metadata, never used as the canonical id), created_at/updated_at.
Campus — id (EntityId), university_id (EntityId, permanent once set — no method exists to reassign a campus to a different university), name (required), normalized_name (derived, same rule as above), coordinates (Coordinates), city/state_region (optional, independently settable from the parent university's — a satellite campus can be in a different city), is_main_campus (bool, defaults False), status (InstitutionStatus), source/external_reference (optional), created_at/updated_at.
Business rules to enforce here: id and university_id (on Campus) are permanent. normalized_name is always derived, never set directly, so it can't drift out of sync with official_name/name. Give both entities an update method that only touches the fields being changed, same partial-update discipline as Profile.
Tests you must write: tests/unit/university_location/domain/test_coordinates.py (valid coordinates construct; latitude/longitude outside range each raise ValueError; boundary values ±90/±180 are valid, not rejected) and tests/unit/university_location/domain/test_entities.py (normalized_name derives correctly from mixed-case, extra-whitespace input for both entities; id/university_id have no way to change after construction).

CHUNK 3 — APPLICATION LAYER & USE CASES
[FOR YOU — GEMINI CLI]
Files to create: one file per use case under application/use_cases/: create_university.py, update_university.py, get_university.py, list_universities.py, create_campus.py, update_campus.py, get_campus.py, list_campuses.py, plus bulk_import.py (Part 15/ADR-047).
Governing rule, same as every previous module: transport-level checks (malformed UUID, missing field) are Pydantic's job in Chunk 6. This layer handles what Pydantic can't: uniqueness, the university-must-be-active-and-exist rule for campus creation, and the compound active/active rule for "list active" queries.
CreateUniversity — steps: normalize the name; check no university with that normalized_name exists (raise UniversityAlreadyExists if one does — and, same race-condition discipline as every prior module, translate a database unique-constraint violation into the same error rather than letting it leak raw); construct and persist the entity; log INFO ("university_created", id, official name); return the response.
CreateCampus — steps: look up the parent university by university_id; if it doesn't exist, raise UniversityNotFound; if it exists but its status isn't ACTIVE, raise InactiveInstitution (you can't add a new campus to a deactivated institution); normalize the campus name and check uniqueness within that university (UniversityAlreadyExists's campus counterpart is CampusAlreadyExists); construct Coordinates from the supplied latitude/longitude, letting an out-of-range value surface as InvalidLocation; persist; log INFO; return the response.
UpdateUniversity/UpdateCampus — steps: partial update, same discipline as every previous module's update use cases — look up, apply only supplied fields, re-derive normalized_name if the name changed, persist, log INFO with the field names that changed.
GetUniversity/GetCampus (by id) — steps: direct id lookup, regardless of ACTIVE/INACTIVE status — an existing reference to a specific id must keep resolving even if the institution was later deactivated; raise UniversityNotFound/CampusNotFound only if the id genuinely doesn't exist at all.
ListUniversities/ListCampuses — steps: paginated (use the shared-kernel PageRequest/Page), filterable by state_region and by a simple case-insensitive substring match on name (no ranking, no fuzzy search — Part 22 is explicit that this stays plain reference-data lookup). Default to status = ACTIVE only unless the caller explicitly asks to include inactive records. ListCampuses additionally enforces the compound rule from ADR-046: an "active" campus list excludes any campus whose parent university isn't also ACTIVE, even if the campus's own stored status is ACTIVE — implement this as a join condition in the repository (Chunk 5), not as a write that touches the campus's own status field.
BulkImport (ADR-047) — steps: accepts a file path to a CSV with columns for university and campus data (exact column names your choice — document them precisely in docs/modules/university_location.md, Chunk 9); for each row, calls CreateUniversity/CreateCampus exactly as already written above — do not duplicate their validation or uniqueness logic here. Rows that fail (duplicate, invalid coordinates) are skipped and collected into a report rather than aborting the whole import; log a WARNING per skipped row with the reason, and an INFO summary at the end (rows processed, created, skipped). This use case is invoked from a script/shell, not an HTTP endpoint — there is no /import route in Chunk 6.
Tests you must write: shared fakes under tests/support/university_location_fakes.py. Cover: university creation success and duplicate rejection; campus creation success, rejection for a nonexistent university, rejection for an inactive university, duplicate-within-university rejection, invalid-coordinate rejection; get-by-id resolving an inactive record; list defaulting to active-only and correctly excluding a campus whose university is inactive even though the campus's own status is active; bulk import processing a small in-memory list of rows with one duplicate, confirming the duplicate is skipped and reported, not fatal.
Acceptance criteria: new tests pass, all against fakes.
