PHASE 3 — DATABASE STRATEGY

CHUNK 3.0 — PostgreSQL Setup
Objective: A local PostgreSQL instance running natively inside Termux — no Docker. Docker requires kernel namespace/cgroup features that standard, non-rooted Android/Termux does not expose, so this environment uses Termux's own postgresql package directly.
Architectural context: ADR-011 (revised) — Postgres runs as a native Termux process, started and stopped explicitly per session, since Termux has no init system to manage it automatically.
Files to create:
scripts/db_bootstrap.sh — one-time setup (install, initdb, create role/database).
scripts/db_start.sh — start the server.
scripts/db_stop.sh — stop the server.
Files to modify:
.env.example — add DATABASE_URL.
.gitignore — ensure the Postgres data directory is not committed (it lives under Termux's $PREFIX, outside the repo, so no repo-level ignore entry is actually needed — confirm this and skip adding one if so).
Implementation instructions:
scripts/db_bootstrap.sh (run once):
Bash
#!/data/data/com.termux/files/usr/bin/bash
set -e
pkg install -y postgresql
mkdir -p "$PREFIX/var/lib/postgresql"
initdb "$PREFIX/var/lib/postgresql"
pg_ctl -D "$PREFIX/var/lib/postgresql" -l "$PREFIX/var/lib/postgresql/server.log" start
sleep 2
createuser -P -s -e camp_match      # you will be prompted; use password "camp_match" for local dev
createdb -O camp_match camp_match_dev
pg_ctl -D "$PREFIX/var/lib/postgresql" stop
echo "Bootstrap complete. Use scripts/db_start.sh to start the server."

scripts/db_start.sh

#!/data/data/com.termux/files/usr/bin/bash
pg_ctl -D "$PREFIX/var/lib/postgresql" -l "$PREFIX/var/lib/postgresql/server.log" start
                
scripts/db_stop.sh
#!/data/data/com.termux/files/usr/bin/bash
pg_ctl -D "$PREFIX/var/lib/postgresql" stop
Make all three executable (chmod +x scripts/db_*.sh).
4. Run scripts/db_bootstrap.sh once. Confirm psql -U camp_match -d camp_match_dev -c "SELECT 1;" returns a row.
5. Add to .env.example:

DATABASE_URL=postgresql+asyncpg://camp_match:camp_match@localhost:5432/camp_match_dev

Standard port 5432 is fine here — there is no host/container port mapping to worry about, since everything runs on the same Termux filesystem.
6. Check $PREFIX/var/lib/postgresql/postgresql.conf — confirm listen_addresses includes localhost (Termux's default initdb usually sets this already; if it's commented out or set to nothing, uncomment and set it to 'localhost' so SQLAlchemy/asyncpg can connect over TCP rather than only a Unix socket).
7. Document in README.md under "Database (Termux)": run scripts/db_bootstrap.sh once after cloning; run scripts/db_start.sh at the start of every dev/test session and scripts/db_stop.sh when done; the server does not survive a Termux/device restart automatically — you always start it manually. If you're running a long session, consider termux-wake-lock (from the Termux:API add-on) so Android doesn't suspend Termux and kill the server mid-session.
You must not: add a docker-compose.yml or any Docker reference back into the project — this environment cannot run it.
Acceptance criteria:
scripts/db_start.sh starts the server with no error; pg_isready -h localhost -p 5432 reports accepting connections.
psql -U camp_match -d camp_match_dev -c "SELECT 1;" succeeds.
scripts/db_stop.sh stops it cleanly

CHUNK 3.1 — SQLAlchemy Setup

Objective: Add SQLAlchemy (async) and asyncpg as dependencies; establish the declarative base with a real naming convention.
Architectural context: ADR-004.
Files to modify:
pyproject.toml — add runtime deps sqlalchemy (>=2.0), asyncpg; dev dep aiosqlite is not needed — tests run against real Postgres per ADR-013, not SQLite.
Files to create:
src/camp_match/platform/db/base.py
Implementation instructions:
poetry add sqlalchemy asyncpg, then poetry add --group dev alembic (Alembic is dev-only tooling, not a runtime dependency of the deployed app).
platform/db/base.py:

from sqlalchemy.orm import DeclarativeBase

NAMING_CONVENTION = {
    "ix": "ix_%(column_0_label)s",
    "uq": "uq_%(table_name)s_%(column_0_name)s",
    "ck": "ck_%(table_name)s_%(constraint_name)s",
    "fk": "fk_%(table_name)s_%(column_0_name)s_%(referred_table_name)s",
    "pk": "pk_%(table_name)s",
}

class Base(DeclarativeBase):
    metadata_naming_convention = NAMING_CONVENTION

        
apply NAMING_CONVENTION via metadata = MetaData(naming_convention=NAMING_CONVENTION) as a class attribute on Base, per current SQLAlchemy 2.0 declarative API — the snippet above shows the convention dict; wire it exactly as SQLAlchemy 2.0's documented pattern for declarative naming conventions requires.)
3. This Base is the only declarative base for the entire project — every module's ORM models (once modules exist) inherit from this one, imported from camp_match.platform.db.base. Do not create a second base.
You must not: define any table/model yet — no business tables exist until the Identity module.
Tests you must write: tests/unit/platform/test_db_base.py — confirms Base.metadata.naming_convention (or equivalent) contains the exact keys above.
Acceptance criteria: new test passes; mypy clean.
