platform/in_memory_event_bus.py — the adapter:

from __future__ import annotations
from collections import defaultdict
from typing import Awaitable, Callable
import structlog
from camp_match.shared_kernel.domain.events import DomainEvent

logger = structlog.get_logger()
EventHandler = Callable[[DomainEvent], Awaitable[None]]

class InMemoryEventBus:
    def __init__(self) -> None:
        self._handlers: dict[type, list[EventHandler]] = defaultdict(list)

    def subscribe(self, event_type: type[DomainEvent], handler: EventHandler) -> None:
        self._handlers[event_type].append(handler)

    async def publish(self, event: DomainEvent) -> None:
        logger.info("domain_event_published", event_type=type(event).__name__, event_id=str(event.event_id))
        for handler in self._handlers[type(event)]:
            await handler(event)
Business rules: modules communicate across boundaries either through direct port calls (synchronous, when one module genuinely needs a response from another) or through events (when the producing module shouldn't need to know who consumes the fact that something happened — e.g. BookingConfirmed triggering a notification). Do not introduce an event for something that has exactly one caller and one callee with a direct dependency already — that's what ports are for.
You must not: wire any real subscriber yet — there are no modules to subscribe. This chunk only proves the mechanism works.
Tests you must write: tests/unit/shared_kernel/test_event_bus.py — a test event subclass gets published, a subscribed handler receives it, an unsubscribed event type triggers no handler, multiple handlers for the same event type all fire.
Acceptance criteria: new tests pass

pagination.py:

from __future__ import annotations
from dataclasses import dataclass
from typing import Generic, TypeVar

T = TypeVar("T")

@dataclass(frozen=True)
class PageRequest:
    page: int = 1
    page_size: int = 20

    def __post_init__(self) -> None:
        if self.page < 1:
            raise ValueError("page must be >= 1")
        if not (1 <= self.page_size <= 100):
            raise ValueError("page_size must be between 1 and 100")

@dataclass(frozen=True)
class Page(Generic[T]):
    items: list[T]
    total: int
    page: int
    page_size: int

unit_of_work.py — port only:
from __future__ import annotations
from typing import Protocol

class UnitOfWork(Protocol):
    async def __aenter__(self) -> "UnitOfWork": ...
    async def __aexit__(self, exc_type: object, exc: object, tb: object) -> None: ...
    async def commit(self) -> None: ...
    async def rollback(self) -> None: ...

Use cases that need a transaction boundary accept a UnitOfWork (or a factory that produces one) as a constructor dependency, and wrap their repository calls in async with uow: ... await uow.commit(). No concrete implementation exists until Phase 3 Chunk 3.4 — that's expected; this port has no consumer yet either, which is fine, since the point of this chunk is to fix the contract now so Phase 3's SQLAlchemy implementation has something exact to satisfy.
Why these two, specifically, belong in the shared kernel and not a module: both are used by every module that will ever list or paginate data, or every module that will ever need an atomic multi-repository write — neither is meaningful scoped to one module, and neither depends on infrastructure to define.

No test for UnitOfWork yet — it's a bare Protocol with no implementation to exercise until Phase 3.
